# 安全与隐私

## API Key

- 对话、截图、日志、Git 和错误报告都不应出现真实 Key。
- 当前已公开过的 Key 必须撤销，不再使用。
- 新 Key 只保存在本机 `.env` 或系统钥匙串；生产版优先接 macOS Keychain。
- 日志脱敏规则至少覆盖 `sk-` 开头的长字符串和 `Authorization` 请求头。

## 简历数据

简历属于高敏感个人信息。使用 DeepSeek 云 API 意味着被发送的文本会离开本机，因此产品界面必须明确提示并获得用户确认。

推荐默认处理：

1. PDF/DOCX 原文件不上传，只在本机提取文本。
2. 分析前删除电话、邮箱、住址、身份证号等与筛选无关的信息。
3. 可选地把姓名替换为 `candidate_id`，模型返回后在本地恢复展示。
4. 请求中不发送本地绝对路径；使用 `file_id` 和页码。
5. 日志只记录请求 ID、模型、token、耗时、状态，不记录全文。
6. 数据库、缓存和 Excel 默认只保存在用户选择的本地工作区。

## 招聘合规

- 不依据性别、年龄、民族、婚育、照片、健康等敏感属性自动评分。
- 系统输出是辅助意见，最终筛选由招聘人员复核。
- 每个结论必须保留证据和模型/规则版本，支持申诉和回溯。
- 模型无法核验的内容写“不确定”，不能用常识补成确定事实。

## 开发检查

提交前运行秘密扫描；测试使用伪造 Key。对异常对象和 SDK 响应做定制序列化，避免请求头或完整简历意外进入日志。
